# 装備仕様書

- 最終更新: 2026-07-12
- 文書状態: 構想段階
- 位置づけ: 装備データの責務と、戦闘・見た目・スキル候補・タグへの接続を定義する。スキル効果の詳細は `docs/specs/スキル仕様書.md`、タグ一致ボーナスの詳細は `docs/specs/タグ仕様書.md` を参照する。

## 1. 基本方針

- 装備データは、戦闘用データと見た目用データを兼用する。
- プレイヤーと敵は同じ `EquipmentMasterData` を参照できる。
- 装備中状態は、現行実装どおり `PartType + EquipmentId` を基本に扱う。
- 装備データごとに、見た目 Sprite / icon / `PartsIndex` と、戦闘で参照する補助情報を持つ。
- 属性の概念は採用しない。
- 装備同士の識別やセット感は、`CategoryTags` などのタグで表現する。

## 2. 装備枠

戦闘上の装備枠は以下を基本とする。

- 頭装備
- 胴装備
- 右手装備
- 左手装備
- アイテム

現行 `PartsType` との主な対応は以下とする。

- 頭装備: `Helmet`
- 胴装備: `Chest`
- 右手装備: `Sword`, `Axe`, `Bow`, `Wand`, `Staff`, `Spear`, `Blunt`, `Crossbow`
- 左手装備: `Shield`, `SubItem`
- アイテム: Dance 効果などに使う独立枠として扱う。現行 `PartsType` との正式対応は別途決める。

## 3. 左手装備

左手装備は `Shield` と `SubItem` の 2 系統を持つ。

- `Shield`: 防御寄りの左手装備として扱う。
- `SubItem`: 攻撃補助寄りの左手装備として扱う。

新仕様では、`Shield` と `SubItem` の違いを属性相性では表現しない。
装備ごとの `BattleStatModifiers`、候補スキル、タグ一致ボーナスで個性を出す。

## 4. 装備マスターデータ

`EquipmentMasterData` は少なくとも以下を扱う。

- `EquipmentId`
- `DisplayName`
- `PartType`
- `PartsIndex`
- `Icon`
- `SortOrder`
- `IsDefaultOwned`
- 見た目 Sprite / 見た目解決用情報
- 候補スキル
- `BattleStatModifiers`
- `CategoryTags`

装備データは、属性、属性相性、弱点、耐性、無効などの情報を持たない。

## 5. タグ

装備は複数のタグを持てる。
現行実装では `EquipmentMasterData.CategoryTags` がその受け皿になっている。

タグは以下に使う。

- UI 分類
- 絞り込み
- 装備セットのテーマ表示
- タグ一致ボーナス
- 将来のロジック分岐補助

タグの詳細は `docs/specs/タグ仕様書.md` を参照する。

## 6. 候補スキル

- 全装備が候補スキルを持てる。
- 1 装備が持てる候補スキルは最大 2 件とする。
- 候補スキルは `BattleSkillMasterData` 参照で持つ。
- 候補スキルは「その装備が提供できるスキル候補」であり、戦闘中に使う実戦用 Skill パレットとは別概念とする。
- 実戦用 Skill パレットは、装備中の各装備が持つ候補スキル群から別途選抜して構成する。
- スキル自体の効果配列、チャージ、成功率、演出は `docs/specs/スキル仕様書.md` を正とする。

現行実装では最大 3 件想定の validation / tooltip が残っているため、実装時に最大 2 件へ合わせる。

## 7. BattleStatModifiers

`BattleStatModifiers` は、装備から戦闘ステータスへ流し込む汎用補正である。

補正対象は広く許可する。

- `Parameter`: `Hp`, `Attack`, `Defense`, `Charge`, `Guard` などの enum 値
- `NamedValue`: 文字列キーで参照する拡張値

補正操作は以下を扱う。

- `Set`: 値を上書きする
- `Add`: 値を加算する
- `Multiply`: 値を倍率で補正する

`Speed` は現行 enum に存在するが、このゲームの戦闘ロジックには合いにくいため削除候補として扱う。
削除するか、互換性のために残すかは実装時に決める。

## 8. NamedValue

`NamedValue` は、enum にまだ存在しない戦闘用の補正値を文字列キーで扱うための逃がし口である。

例:

- `attack.normal.multiplier`
- `attack.double.multiplier`
- `attack.jump.multiplier`
- `damage.final.multiplier`

通常の `Attack` や `Guard` のように enum へ固定するほどではないが、装備やタグ一致ボーナスから調整したい値に使う。
将来よく使う値になった場合は、enum や専用データへ昇格してもよい。

## 9. タグ一致ボーナス

アイテムを除く装備のタグが一定条件で揃った場合、ステータスにボーナス補正を加える。

- `SubItem` は左手装備として扱い、タグ一致ボーナスの対象に含める。
- 除外するのは独立したアイテム枠のみとする。
- ボーナス内容は `BattleStatModifiers` 相当の追加補正として扱う。
- 具体的な成立条件や補正値は、タグ仕様書側で後から定める。

## 10. 現行実装との差分メモ

現行実装では、以下が新方針と異なる。

- `EquipmentMasterData.AssignableSkills` は最大 3 件想定になっている。
- 通常攻撃属性は `NormalAttackAttribute` として右手装備から解決している。
- 被ダメージ側の属性補正は `AttributeModifiers` として胴装備から解決している。
- `BattleSkillMasterData` などに属性参照が残っている。
- タグ一致ボーナスは未実装である。

新仕様へ寄せる際は、属性系の情報を撤去または無効化し、タグ、候補スキル、`BattleStatModifiers` へ役割を寄せる。
