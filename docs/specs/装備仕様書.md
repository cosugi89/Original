# 装備仕様書

- 最終更新: 2026-08-16
- 文書状態: 実装反映中
- 位置づけ: 装備データの責務と、戦闘・見た目・スキル候補・タグへの接続を定義する。スキル効果の詳細は `docs/specs/スキル仕様書.md`、タグ一致ボーナスの詳細は `docs/specs/タグ仕様書.md`、装備変更 UI の入口は `docs/specs/MainScene仕様書.md` を参照する。

## 1. 基本方針

- 装備データは、戦闘用データと見た目用データを兼用する。
- プレイヤーと敵は同じ `EquipmentMasterData` を参照できる。
- 装備中状態は、現行実装どおり `PartType + EquipmentId` を基本に扱う。
- 装備データごとに、見た目 Sprite / icon / `PartsIndex` と、戦闘で参照する補助情報を持つ。
- 属性の概念は採用しない。
- 装備同士の識別やセット感は、`CategoryTags` などのタグで表現する。

## 2. 装備枠

戦闘上の装備枠は以下を基本とする。

- 頭装備
- 胴装備
- 右手装備
- 左手装備
- アイテム

現行 `PartsType` との主な対応は以下とする。

- 頭装備: `Helmet`
- 胴装備: `Chest`
- 右手装備: `Sword`, `Axe`, `Bow`, `Wand`, `Staff`, `Spear`, `Blunt`, `Crossbow`
- 左手装備: `Shield`, `SubItem`
- アイテム: Dance 効果などに使う独立枠として扱う。現行 `PartsType` との正式対応は別途決める。

## 3. 左手装備

左手装備は `Shield` と `SubItem` の 2 系統を持つ。

- `Shield`: 防御寄りの左手装備として扱う。
- `SubItem`: 攻撃補助寄りの左手装備として扱う。

新仕様では、`Shield` と `SubItem` の違いを属性相性では表現しない。
装備ごとの `BattleStatModifiers`、候補スキル、タグ一致ボーナスで個性を出す。

## 4. 装備マスターデータ

`EquipmentMasterData` は少なくとも以下を扱う。

- `EquipmentId`
- `DisplayName`
- `PartType`
- `PartsIndex`
- `Icon`
- `SortOrder`
- `IsDefaultOwned`
- 見た目 Sprite / 見た目解決用情報
- 候補スキル
- `DanceSkill`
- `BattleStatModifiers`
- `CategoryTags`

装備データは、属性、属性相性、弱点、耐性、無効などの情報を持たない。

## 5. タグ

装備は複数のタグを持てる。
現行実装では `EquipmentMasterData.CategoryTags` がその受け皿になっている。

タグは以下に使う。

- UI 分類
- 絞り込み
- 装備セットのテーマ表示
- タグ一致ボーナス
- 将来のロジック分岐補助

タグの詳細は `docs/specs/タグ仕様書.md` を参照する。

## 6. 候補スキル

- 全装備が候補スキルを持てる。
- 1 装備が持てる候補スキルは最大 2 件とする。
- 候補スキルは `BattleSkillMasterData` 参照で持つ。
- 候補スキルは「その装備が提供できるスキル候補」であり、戦闘中に使う実戦用 Skill パレットとは別概念とする。
- 実戦用 Skill パレットは、装備中の各装備が持つ候補スキル群から別途選抜して構成する。
- スキル自体の効果配列、チャージ、成功率、演出は `docs/specs/スキル仕様書.md` を正とする。
- 武器ごとの固定 Skill パレットマスターは初期仕様では持たず、保存済みロードアウトだけを正とする。
- `DanceSkill` はアイテム相当の装備が提供する Dance 効果の受け口である。現行 `PartsType` に独立アイテム枠がないため、設定先の正式な枠は今後決める。

現行実装の validation / tooltip / DTO 変換は最大 2 件に合わせている。
現行デモデータでは、`PartsType` ごとに 2 件の候補スキルを作成し、その種類の全 `EquipmentMasterData` へ同じ 2 件を割り当てている。
対象種類は `Axe`, `Beard`, `Blunt`, `Bow`, `Chest`, `Crossbow`, `Eye`, `Hair`, `Helmet`, `Shield`, `Spear`, `Staff`, `SubItem`, `Sword`, `Wand` とする。

## 7. BattleStatModifiers

`BattleStatModifiers` は、装備から戦闘ステータスへ流し込む汎用補正である。

補正対象は広く許可する。

- `Parameter`: `Hp`, `Attack`, `Defense`, `Charge`, `Guard` などの enum 値
- `NamedValue`: 文字列キーで参照する拡張値

補正操作は以下を扱う。

- `Set`: 値を上書きする
- `Add`: 値を加算する
- `Multiply`: 値を倍率で補正する

旧 `Speed` は `BattleSkillParameterType.LegacySpeed = 4` として互換用に残す。
新仕様の戦闘計算では使用せず、装備補正で指定されても無視する。

## 8. NamedValue

`NamedValue` は、enum にまだ存在しない戦闘用の補正値を文字列キーで扱うための逃がし口である。

例:

- `attack.normal.multiplier`
- `attack.double.multiplier`
- `attack.jump.multiplier`
- `damage.final.multiplier`

通常の `Attack` や `Guard` のように enum へ固定するほどではないが、装備やタグ一致ボーナスから調整したい値に使う。
将来よく使う値になった場合は、enum や専用データへ昇格してもよい。

## 9. タグ一致ボーナス

アイテムを除く装備のタグが一定条件で揃った場合、ステータスにボーナス補正を加える。

- 現行実装では、`Helmet`、`Chest`、右手装備、左手装備をタグ一致判定の対象にする。
- `SubItem` は左手装備として扱い、タグ一致ボーナスの対象に含める。
- 除外するのは独立したアイテム枠のみとする。
- ボーナス内容は `BattleStatModifiers` 相当の追加補正として扱う。
- 初期の成立条件は、タグ一致判定対象の全装備が同じタグを持つ全一致とする。
- 初期補正値は、タグ仕様書側で定める `Attack` への `Multiply 1.10` とする。
- `BattleEquipmentDerivedDataResolver` は対象装備の `CategoryTags` を集約し、2 装備以上で同じタグを持つものを `TagMatchCandidates` として出力する。
- 同一装備内に同じタグが重複していても、一致数は 1 装備ぶんとして扱う。
- 全一致条件を満たしたタグは `TagBonusMatches` として出力する。
- `TagBonusMatches` は成立済みのタグ一致であり、`TagBonusStatModifiers` として通常の `BattleStatModifiers` の後ろに追加される。

## 10. 現行実装との差分メモ

現行実装では、旧属性実装の互換フィールドが残っている。

- `EquipmentMasterData.NormalAttackAttribute` 相当の serialized field は既存 asset 保護のため残っている。
- `EquipmentMasterData.AttributeModifiers` 相当の serialized field は既存 asset 保護のため残っている。
- これらは旧属性実装の互換フィールドであり、新仕様の戦闘計算や UI には使用しない。
- runtime DTO への変換、装備派生データ、戦闘コンテキストへの接続は外している。
- タグ一致候補の生成、全一致による成立判定、`Attack` への初期補正適用は実装済みである。

今後はタグ、候補スキル、`BattleStatModifiers` へ役割を寄せる。
旧属性 field / asset の完全削除は、既存 serialized data の移行方針を決めてから行う。

## 11. MainScene Status タブとの接続

現行 `MainScene` の Status タブ初期実装では、装備変更のみを扱う。

- `EquipmentMasterDatabase` は、キャラクター見た目パーツ由来の `EquipmentMasterData` を参照する。
- キャラメイク由来で生成した装備マスターは、正式な入手 / 解放フローが入るまで `IsDefaultOwned = true` とし、Status タブ上で選択可能な初期装備として扱う。
- Status タブの選択対象は、頭装備、胴装備、右手装備、左手装備である。
- `Item` 枠は現行 Status タブでは非表示、未接続とする。
- 装備一覧の項目クリックでは装備詳細ダイアログを開き、ダイアログ内の `Equip` ボタン押下時に `UserData.Profile.Avatar.Parts`、プレイヤープレビュー、実戦用 Skill ロードアウト整理、セーブへ反映する。
- 装備変更により使えなくなった Skill は、`BattleSkillLoadoutService.EnsureUsableLoadout(...)` により自動で外す。
