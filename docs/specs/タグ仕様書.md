# タグ仕様書

- 最終更新: 2026-09-25
- 文書状態: 実装反映中
- 位置づけ: 属性を廃止した後の、装備識別子、装備テーマ、一致ボーナスの骨格を定義する。

## 1. 基本方針

- 属性相性の概念は採用しない。
- 攻撃属性、防御属性、属性相性テーブル、弱点、耐性、無効は新仕様では扱わない。
- 装備同士の識別やセット感は、`CategoryTags` などのタグで表現する。
- タグは「敵との相性表」ではなく、「装備セットのテーマ」や「プレイスタイル補助」を表す。
- タグ一致によるボーナスは、`BattleStatModifiers` 相当の追加補正として扱う。

## 2. タグの役割

タグは、装備を横断してグループ化するための短いキーワードである。

主な用途は以下。

- UI での分類、絞り込み、検索
- 装備セットのテーマ表示
- 装備同士の一致ボーナス判定
- 将来のロジック分岐補助

タグは、プレイヤーに覚えさせる相性表として使わない。
タグが増えすぎると属性の言い換えになってしまうため、数を絞り、装備のプレイ感が変わる単位で使う。
各装備が持てるタグは最大2件とする。

## 3. タグ例

具体的なタグ名は未確定だが、方向性としては以下を候補にする。

- `軽装`: Roll、回避、移動感を補助する装備群
- `重装`: HP、Guard、防御寄りの装備群
- `技巧`: Charge、Skill 回転、細かい操作を補助する装備群
- `突撃`: Attack、Jump Attack、攻撃寄りの装備群

これらは例であり、正式なタグ一覧は別途決める。

## 4. タグ一致ボーナス

アイテムを除く装備のタグが2部位以上で一致した場合、最終 `HP / Attack / Defense` にボーナスを加える。

- 判定対象は装備中の `Helmet`、`Chest`、右手装備、左手装備とする。`PartsType.SubItem` は左手装備として含め、独立したItem枠は対象外とする。
- 同一タグの一致部位数が2 / 3 / 4の場合、一致した各装備の能力値加算分へそれぞれ25 / 50 / 75%のボーナスを加える。
- 成立したタグはすべて適用する。複数タグを持つ装備は、成立した各タグのボーナスを重ねて受ける。
- タグボーナスは基礎値、Traits、Insights、タグを持たない装備の加算値には掛けない。戦闘中の一時補正やNamedValueにも掛けない。

最終ステータスは、基礎値、Traits、Insights、全装備の加算値、各成立タグの一致ボーナスを順に足して求める。タグごとの一致状況と加算結果はCharacter上で確認できるようにする。

## 5. 一致条件

タグごとの一致部位数だけで判定する。特定部位の指定やシリーズIDは使わない。
同一装備内で同じタグを重複登録しても一致数は1部位として扱う。

## 6. タグと NamedValue

タグはプレイヤーに見える識別子として扱う。
`NamedValue` は内部補正値のキーとして扱う。

例:

- タグ: `軽装`
- 補正: `roll.guard.multiplier` や `damage.final.multiplier`

プレイヤーに見せる主語はタグや装備テーマにし、`NamedValue` の文字列キーそのものは基本的に UI に出さない。

## 7. レベルデザイン上の注意

タグを敵ごとの有利不利表として使うと、属性を捨てた意味が薄れる。
タグは「この敵にはこのタグが正解」ではなく、「この装備セットではどの行動が強くなるか」を作るために使う。

敵ごとの差別化は、以下で作る。

- 盤面パターン
- 危険配置
- 敵Skill構成
- Skill / Attack の価値
- 装備が提供する候補スキル

タグ一致ボーナスは、敵相性よりもプレイヤーのビルド傾向を支える役割に寄せる。

## 8. 現行実装との差分メモ

現行実装には、旧属性仕様に由来する以下の互換データが残っている。

- `EquipmentMasterData.NormalAttackAttribute`
- `EquipmentMasterData.AttributeModifiers`
- `BattleSkillMasterData` の属性参照
- `AttributeMasterData`

runtime DTO、装備派生データ、戦闘コンテキスト、ダメージ計算、初期 UI への旧属性接続は外している。
新仕様ではこれらをタグ/装備テーマ/候補スキル/`BattleStatModifiers` へ置き換える。
旧属性 field / asset の完全削除は、既存 serialized data の移行方針を決めてから行う。

タグ一致の現行実装は全一致時のAttack `×1.10` であり、本仕様の一致部位数ごとの加算ボーナスへ置換する必要がある。
