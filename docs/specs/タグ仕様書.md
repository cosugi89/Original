# タグ仕様書

- 最終更新: 2026-08-11
- 文書状態: 実装反映中
- 位置づけ: 属性を廃止した後の、装備識別子、装備テーマ、一致ボーナスの骨格を定義する。

## 1. 基本方針

- 属性相性の概念は採用しない。
- 攻撃属性、防御属性、属性相性テーブル、弱点、耐性、無効は新仕様では扱わない。
- 装備同士の識別やセット感は、`CategoryTags` などのタグで表現する。
- タグは「敵との相性表」ではなく、「装備セットのテーマ」や「プレイスタイル補助」を表す。
- タグ一致によるボーナスは、`BattleStatModifiers` 相当の追加補正として扱う。

## 2. タグの役割

タグは、装備を横断してグループ化するための短いキーワードである。

主な用途は以下。

- UI での分類、絞り込み、検索
- 装備セットのテーマ表示
- 装備同士の一致ボーナス判定
- 将来のロジック分岐補助

タグは、プレイヤーに覚えさせる相性表として使わない。
タグが増えすぎると属性の言い換えになってしまうため、数を絞り、装備のプレイ感が変わる単位で使う。

## 3. タグ例

具体的なタグ名は未確定だが、方向性としては以下を候補にする。

- `軽装`: Roll、回避、移動感を補助する装備群
- `重装`: HP、Guard、防御寄りの装備群
- `技巧`: Charge、Skill 回転、細かい操作を補助する装備群
- `舞踏`: Dance 効果や支援行動を補助する装備群
- `突撃`: Attack、Jump Attack、攻撃寄りの装備群

これらは例であり、正式なタグ一覧は別途決める。

## 4. タグ一致ボーナス

アイテムを除く装備のタグが一定条件で揃った場合、ステータスにボーナス補正を加える。

- ボーナスは `BattleStatModifiers` 相当の追加補正として扱う。
- 対象装備は、装備中の非アイテム装備とする。
- 現行実装では `Helmet`、`Chest`、右手装備、左手装備を判定対象とする。
- `PartsType.SubItem` は左手装備として対象に含める。
- 独立したアイテム枠は対象外とする。
- 初期のボーナス成立条件は全一致とする。
- 初期補正値は、全一致タグ 1 件につき `Attack` へ `Multiply 1.10` を加える。

`BattleEquipmentDerivedDataResolver` は、対象装備の `CategoryTags` を集約し、同じタグを持つ装備が複数あるかを `TagMatchCandidates` として出力する。
同一装備内に同じタグが重複していても、タグ一致数は 1 装備ぶんとして数える。
`TagMatchCandidates` は 2 装備以上で一致したタグを候補として持ち、対象装備すべてを覆っているかは `CoversAllEligibleEquipment` で判定できる。
初期条件を満たしたタグは `TagBonusMatches` に出力する。
成立済みタグ一致ボーナスは `TagBonusStatModifiers` として生成し、通常の `BattleStatModifiers` の後ろに追加して戦闘ステータスへ適用する。

## 5. 一致条件

初期仕様では、全一致だけを成立条件として扱う。

- 対象装備が 2 件以上ある。
- あるタグが、タグ一致判定対象の全装備に付いている。
- 装備ごとに複数タグを持てるため、複数のタグが同時に全一致条件を満たす可能性はある。

一定数一致、部位指定一致、シリーズ一致は初期仕様では扱わない。
複雑なセット条件を増やす場合は、UI 表示と説明文で理解できる範囲に留める。

## 6. タグと NamedValue

タグはプレイヤーに見える識別子として扱う。
`NamedValue` は内部補正値のキーとして扱う。

例:

- タグ: `軽装`
- 補正: `roll.guard.multiplier` や `damage.final.multiplier`

プレイヤーに見せる主語はタグや装備テーマにし、`NamedValue` の文字列キーそのものは基本的に UI に出さない。

## 7. レベルデザイン上の注意

タグを敵ごとの有利不利表として使うと、属性を捨てた意味が薄れる。
タグは「この敵にはこのタグが正解」ではなく、「この装備セットではどの行動が強くなるか」を作るために使う。

敵ごとの差別化は、以下で作る。

- 盤面パターン
- 危険配置
- 敵戦型
- Skill / Dance / Attack の価値
- 装備が提供する候補スキル

タグ一致ボーナスは、敵相性よりもプレイヤーのビルド傾向を支える役割に寄せる。

## 8. 現行実装との差分メモ

現行実装には、旧属性仕様に由来する以下の互換データが残っている。

- `EquipmentMasterData.NormalAttackAttribute`
- `EquipmentMasterData.AttributeModifiers`
- `BattleSkillMasterData` の属性参照
- `AttributeMasterData`

runtime DTO、装備派生データ、戦闘コンテキスト、ダメージ計算、初期 UI への旧属性接続は外している。
新仕様ではこれらをタグ/装備テーマ/候補スキル/`BattleStatModifiers` へ置き換える。
旧属性 field / asset の完全削除は、既存 serialized data の移行方針を決めてから行う。
