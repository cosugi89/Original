# チュートリアル仕様書

- 最終更新: 2026-10-13
- 文書状態: 発火・進行・保存・UI表示の基盤とMainScene／BattleScene／既存Dialogの接続を実装。HomeのAngel導入会話を登録・有効化済み。Battleの説明とResurgence差分は未完了。
- 位置づけ: 任意の画面・戦闘状態から発火し、指定UIだけ操作可能にするチュートリアル。世界観上の内容は `世界観仕様書.md` を正とする。

## 1. 仕様確認で補った契機

タブやDialogの初回表示、Stage別のBattle開始、戦闘中の進捗だけでなく、次を扱う。

- Home構築完了後、TitleのLoading Canvasが消え、Angelが登場してからHomeReadyを通知する。HUDはまだ非表示・操作不可とし、この時点で実行できるチュートリアルがすべて終了してから表示する。
- 保存状態の更新。Missionクリア、報酬・重要品・Insightの取得、Traitや装備等の更新による条件を再照合する。変更内容ごとの予測フラグを複製せず、既存の進捗と所持品を読む。
- セーブ読み込み後、および画面の表示準備が完了した後の保存状態の再照合。前のSceneで条件を満たした案内も、対応画面の準備が整った時点で開始できる。
- Resurgence開始、人間ボス結果の記録、上位存在到達。将来の物語導線でも同じ通知APIを利用可能。
- 入力確定と操作結果の区別。パスの確定／不成立、Skill選択／実使用、Attack解決、Goal解決、危険マスでの被弾、ターン解決、Battle終了を区別する。

救済条件をUIで明示しない仕様を維持する。ボス結果や救済経験は条件として使えるが、条件の文面を自動生成してプレイヤーに公開しない。

## 2. マスターデータ

`TutorialMasterData`を一連の案内ごとに1つ作り、`TutorialMasterDatabase`の一覧へ登録する。識別子は固定の正の`int`。IDを変更・再利用すると完了記録の意味が変わるため、公開後は固定する。SceneはDatabaseとTutorial PrefabをInspectorから直接参照し、runtimeでパス検索しない。

| 項目 | 用途 |
| --- | --- |
| TutorialId / IsEnabled | 識別と有効化 |
| RepeatForDebug | Editor／Development Buildで完了・訪問済みを無視して契機ごとに再生する初期値。通常ビルドには適用しない |
| Trigger / TriggerKey | 判定の契機と通知Keyの絞り込み。空Keyは任意 |
| RequiredScopeKey | 対象の画面インスタンスが表示準備済みの場合だけ開始 |
| OnlyFirstVisit | 厳密な初回訪問限定。TabReady／DialogReadyでだけ使う |
| Repeat | OncePerSave、OncePerBattle、EveryOccurrence |
| Priority | 同時候補の優先度。高いものから開始。同値はTutorialId順 |
| Conditions | すべて満たしたとき成立する型付き条件 |
| Steps | メッセージ、強調、許可操作、手、進行条件 |

条件はStageクリア・解放・現在Stage、ターン下限、プレイヤーHP割合上限、別Tutorial完了、Resurgence、上位存在到達、Item所持数下限、指定ボスの結果、救済経験、装備所持、Traitの配置NodeのLevel下限、SkillスロットのReady状態。Stage、前提Tutorial、Equipment、AbilityTreeはSOを直接参照する。Traitは既存のTreeIdとTreeNodeIdの組で保存済みLevelを照合し、新しい進捗を複製しない。Expected=falseで条件の否定を表現する。現在のStageは表示番号ではなくStageIdで照合する。複雑な任意式やUserDataのフィールド名を解釈する仕組みは持たない。

## 3. Stepと操作対象

Stepはマスター内のSerializable配列。次を設定できる。

- 本文・話者名。本文空ならメッセージを非表示にできる。Continueボタンは設けず、会話は画面全体のタップで進める。
- ResurgenceMessage。任意の差分本文であり、TMP rich textによる赤字を使える。差分が必要な導入を完了済み案内とは別に再生する場合は、別TutorialIdとIsResurgence条件を使う。
- Highlights。複数UIの矩形に余白を付けて暗幕をくり抜く。
- AlphaHighlight。任意のRawImageを1つ指定し、Textureのアルファに沿って暗幕を除く。透過部分の背景は暗いままで、半透明の輪郭は連続的に透過する。矩形のHighlightsと独立して指定可能。
- MessageAtBottom。Angel導入ではtrueとし、上側のAngelを隠さないようメッセージを下側へ配置する。
- InteractionTarget。操作を許可するUIを1つ指定する。空なら背後の操作を全遮断する。
- HandTarget、ShowHand、HandOffset。強調と操作対象とは独立して手を表示する。手は対象へ追従し、unscaled timeで小さく往復する。
- AllowDescendantsAndDrag。盤面全体のトレースなどで対象の子とドラッグを許可する。通常のButtonではfalseにする。
- Advance。TargetButton、Signal、ScreenTapのいずれか。旧ContinueButton（値0）のマスターはEditor配線ツールでScreenTapへ移行する。既存TargetButton=1、Signal=2、ScreenTap=3の値は維持する。
- ScreenTapは穴の内側・暗幕・メッセージを含む画面全体で台詞を送る。背後への入力を全遮断し、InteractionTargetは無視する。Continueボタンは表示しない。ShowHandは独立設定で、Home会話ではfalse。
- CompletionSignal / CompletionKey。ゲーム処理の成立や次画面の準備完了を待つ。空Keyは任意。
- TargetWaitSeconds。次画面の対象を待つ時間。上限を超えると未完了で中断する。

SOにはシーンのGameObjectを保存しない。`TutorialScope`のScopeKeyとTargetKeyで指定し、Scope内のInspector参照または`Bind(key, instance)`で実物を登録する。空ScopeKeyは開始元Scope、開始元がない場合はRequiredScopeKeyを利用する。画面をまたぐStepにはScopeKeyを明示する。

Scopeは表示準備を1フレームとレイアウト更新後まで待ち、登録とready通知を行う。非表示時に解除する。同じGameObjectの再表示もGenerationで区別し、過去の表示回の候補を後から実行しない。動的一覧にはPrefabではなく生成済みインスタンスを渡す。

## 4. 入力と描画

- `TutorialController`がPrefabの見た目・座標追従・入力制限を担当する。`TutorialManager`が発火、実行中のStep、完了記録を担当する。
- TutorialMessageは`Assets/Resources/Prefabs_Sample/Demo/Scenes/Tutorial.prefab`の枠・本文余白・話者欄・font設定を使用する。サイズは約808.2×249.85、本文は枠に対して横110・縦88.7を引いた領域。ボタン用の余白や画面比率による引き伸ばしは設けない。サンプルのデモ人物肖像は除く。通常配置はサンプルと同じ画面中心から上に121.37、MessageAtBottomでは画面下側（anchor y=0.19）に移動し、固定サイズを維持する。
- 本文は`maxVisibleCharacters`で1文字ずつ表示する。既定速度は40文字/秒でPrefabのcharactersPerSecondから調整可能。unscaledDeltaTimeを使い、全文に対して改行・自動font調整を決めてから表示文字数だけ増やすため、文字送り中にレイアウトが変わらない。TMP rich textのタグは全文を保持し、タグ自体を1文字として数えない。
- ScreenTapで文字送り中にタップすると全文だけ表示する。全文表示後の次のタップで次Stepへ進み、全文表示と同じフレームの別タップは台詞送りに使わない。TargetButtonやSignalによる操作成立時のStep進行は文字送りで遅延させない。次Stepは0文字から再開し、中断時に更新を停止する。
- Tutorial Prefab自身にScreenSpaceOverlay Canvasを持ち、sortingOrder=31000で表示する。既存のDialogCanvas=30000より前面。Main/BattleのCanvasの描画方式から独立する。31000以上の別Canvasや上位sorting layerを追加する場合は、UI全体の描画順も見直す。
- 対象UIは元の親階層に残す。複製や一時的な親変更は行わない。対象Canvasのカメラで画面座標に変換して穴と手を追従させる。
- `TutorialBackdropGraphic`が矩形の穴を描画する。複数の穴が重なる場合も、暗幕を重ね描きしない。
- AlphaHighlightがあるStepでは、配線済みの`TutorialAlphaBackdrop.mat`を表示インスタンスごとに複製し、GPUでRawImageのTextureアルファを参照する。RenderTextureの更新に追従し、runtimeのCPU readbackは行わない。uvRect、RawImageのcolor.a、親CanvasGroupのalphaを反映する。対象はCanvas上で軸に沿った矩形のRawImageとし、矩形のHighlightPaddingはアルファ強調には適用しない。対象の非表示・破棄・Texture消失は未完了で中断する。
- 全面の入力矩形はアルファ穴の描画とは独立して保持する。ScreenTapはEventSystemの指離しクリックで進み、スワイプ、同じフレームの表示起点クリック、同一Stepへの複数指のクリックで誤って台詞を進めない。次Stepの表示と完了処理はManagerのLateUpdateで行い、終了したタップを背後のUIへ流さない。
- `TutorialInputRaycaster`が元のRaycasterの当たり順位を保って、許可対象の実際の当たりだけ返す。穴の余白や背後の別Buttonは操作不可。対象を覆う別UIを透過して操作しない。
- 通常のButtonではそのButtonへクリックが届く子Graphicだけを許可し、入れ子の別Buttonは許可しない。親のScrollRect等へのドラッグ・スクロール伝播を抑止する。
- キーボード・ゲームパッドのナビゲーションを停止し、選択を解除する。終了時に元の有効な選択と設定を復元する。
- チュートリアル中に作られたRaycasterも捕捉する。元から無効なRaycasterは終了後も無効のまま。
- Input.GetMouseButton、タッチ、独自のInput Actionなどで直接UIを操作するコードはRaycasterを通らない。そのような新しいUI入力を追加する場合は、Tutorialの操作許可と統合する。既存の盤面の指離し処理は、許可された盤面トレースだけを確定する。

## 5. 発火、待機、中断

通知をManagerに渡し、LateUpdateで候補とStepを処理する。同時実行は1件で、実行中の案内に割り込まない。開始前に条件・Scope・対象の存在と操作可能状態を再照合する。優先候補の対象が準備中なら、開始可能な別候補を選べる。

Buttonの元の処理はそのまま実行し、Tutorialのリスナーだけ追加・解除する。Buttonで画面を閉じた場合は、対象消失判定より先に次Stepへ進める。同一通知を複数Stepの完了に使わず、Step開始前に届いた通知も完了に使わない。

指を押している間は新規の案内を開始しない。戦闘はターン演出中に新規表示しない。許可されたパスの実行でターン処理が始まる場合は表示と入力制限を一時解除し、ゲーム側の既存入力ロックで演出中の操作を止める。解決結果の通知後、次の操作可能な区切りで次Stepを表示する。Time.timeScaleは変更しない。

対象の破棄・非表示・Buttonの操作不能化、Sceneの破棄、外部からの`Cancel()`で未完了として中断する。次の表示対象が準備中なら暗幕を解除して待つ。中断時はイベント購読・Raycaster・ナビゲーションを復元する。

## 6. 保存

`UserData.Tutorial`の`TutorialProgressData`を使う。

- CompletedTutorialIds: OncePerSaveの完了ID。完了時に即時保存する。
- VisitedScopeKeys: TabReady／DialogReadyの契機とScopeKeyを組み合わせた訪問記録。初回か判定してから登録し保存する。
- OncePerBattleの再生済みIDと実行中のStepはメモリだけに保持する。新しいBattleReadyで戦闘内記録を解除する。

通常の初回案内はOnlyFirstVisit=false、OncePerSaveとする。途中中断しても次に開いたとき再生できる。OnlyFirstVisit=trueは厳密な初回だけの案内で、条件不足や中断があっても再訪時には再生しない。

中断したStep番号は保存せず、再発火時は先頭から再生する。Resurgence開始時にTutorial完了・訪問記録は消さない。周回ごとの再生回数管理は今回の実装に含めない。古いセーブのTutorial欄やリストの欠落はNormalizeで空として補う。

ResurgenceStarted、BossResultRecorded、HigherBeingReachedはSceneをまたぐ状態通知として、Managerが未配置のSceneで発行された場合や、候補を開始する前にSceneが終わった場合もメモリで引き継ぐ。次のManagerで現在の状態と画面を再照合する。キーと契機が同じ通知はまとめる。閉じたタブ・Dialogや前のBattleの操作通知は引き継がない。この通知待ちはアプリ終了をまたいで保存せず、再起動後にも案内が必要な場合はUserDataChangedまたはHomeReadyと未完了・進捗条件を組み合わせる。

## 7. 接続と作成手順

MainSceneとBattleSceneにTutorialSystemを配線済み。Mainの5タブ、Progressの3サブタブにScopeを配置。既存のDialogBase派生Prefabには型名をScopeKey、Buttonの相対Transform pathをTargetKeyとして登録している。

MainのScopeにはCharacterTab、ProgressTab、HomeTab、MissionsTab、ArmoryTabを登録する。BattleにはBoardとSkillSlot0〜のButtonを登録する。Slot番号は0始まり。盤面セル等の個別対象は、画面側で追加のBindを行う。

`Main.Home`のScopeには`AngelPreview`として`Home/PanelContent/PanelTop/PreviewImage`を登録する。常駐するAngelHomeをPreviewCameraでRenderTextureへ描画した既存の表示を使い、別のAngelを生成しない。PreviewCameraは背景alpha=0、RenderTextureはアルファを保持する形式とする。

有効な`Home-AngelIntroduction.asset`（TutorialId=1101）はHomeReady／Main.Home、RequiredScopeKey=Main.Home、Priority=200、OncePerSave、IsResurgence=falseで開始する。Angelの英語4台詞で、休息場所・赤目の危険・Missions・CharacterとArmoryでの準備を案内する。全StepがScreenTap、AlphaHighlight=Main.Home/AngelPreview、MessageAtBottom=true、操作対象未指定、手なし。救済条件やAngelの本性は開示しない。最後の台詞を送ると完了を保存し、続けて実行できる案内があれば待つ。すべて終了した後にHUDを表示して通常操作へ戻す。中断時は次のHomeReadyで先頭から再試行する。

Home入口は「祭壇・小道具の構築 → 完成保持 → Loadingのフェードアウト完了・破棄 → Angel登場 → HomeReadyでチュートリアル → 全案内終了 → HUDフェードイン・入力解放」の順とする。構築要求のないMainScene直接起動やBattleからの復帰ではパーツを即時完成表示し、Angel・HomeReady・案内終了・HUDの順は共通にする。Tab切替だけではこの入場処理を再実行しない。

`HomeEntranceDirector`は`TutorialManager.PlayReadyTutorials`を待つ。通知を出した直後のIsRunning=falseで終了扱いにせず、LateUpdateによる条件照合を最低1回待つ。実行中、処理待ち通知、現在画面で開始できる候補がある間はHUDを解放しない。完了保存で発火した後続案内も待つ。条件不成立、完了済み、無効の案内は開始しない。別画面や非表示HUDを操作する候補はこの段階では待たず、対象画面やHUDの準備後に通常の進行判定へ渡す。開始済み案内の対象消失・中断・待機上限超過でも、残る実行可能な案内がなければHUDを解放する。

HUDのCanvasGroupはHomeのPanelBottomとResourceBar_Group／MainTabLayoutとする。AngelのPreviewImageを含むPanelContentのCanvasGroupはalpha=1に維持し、案内前にAngelがHUDと一緒に消えることを防ぐ。UIフェード中は入力を無効にし、フェード完了後に小道具Buttonを含めて有効にする。チュートリアルがない場合も通知の照合後、そのままHUD表示へ進む。

Home導入は`RepeatForDebug=true`であり、Editor／Development Buildでは完了後もHomeReadyのたびに再生できる。通常ビルドはOncePerSaveのまま。毎フレーム自動で再開せず、通知の契機ごとに再生する。

### デバッグシート

DebugSheetの`Tutorials`ページは現在SceneのDatabaseを一覧表示する。TutorialManagerが未配置のSceneではMainまたはBattleへ移動して`Refresh`する。`Refresh`は完了・繰り返し設定を再取得する。

- `Completed`: 各TutorialIdの完了フラグをON/OFFし、セーブへ即時保存する。OFF時は同IDの戦闘内再生済み記録も解除する。対象の実行中Step・候補は解除する。訪問履歴は変更しないため、OnlyFirstVisitによる再生は別の条件として残る。
- `Repeat For Debug`: 各IDの繰り返し設定をセッション限定で上書きする。完了・戦闘内再生済み・初回訪問の制限を無視し、その他の発火条件と対象UIの準備は照合する。Editor／Development Buildだけに適用し、アプリ再起動時はSOの初期値に戻る。完了フラグ自体は消さず、OFFにすると通常の完了制限へ戻る。
- `Replay`: 現在画面で先頭から再生する。Enabled・発火条件・完了制限を無視するが、必要なScopeと最初の対象UIが未表示、表示準備中、別Tutorialを実行中の場合は開始しない。受理時はDebugSheetを閉じて表示する。元の完了・訪問履歴・戦闘内再生済み記録を変更せず、デバッグ再生の終了も新しい完了として保存しない。再生中の対象消失や待機上限は通常と同じく中断する。

Editorメニュー`The Red Fever/Tutorial/Setup Home Conversation`で追加配線・マスター登録を行える。既存の会話アセットの台詞や設定は上書きせず、登録済みデータを維持する。

`The Red Fever/Tutorial/Setup Message Design`はサンプルからTutorialMessageのデザインを再配線する。runtimeのPrefab参照とマスターの既存ID・台詞は維持する。手動でメッセージのデザインを変更した後は、このEditorツールを再実行するとサンプル準拠へ戻る。

1. Createメニュー `The Red Fever/Master Data/Tutorial`でマスターを作る。
2. TutorialId、Trigger、条件、Stepsを設定する。
3. `Assets/Resources/MasterData/Tutorial/TutorialMasterDatabase.asset`に登録する。
4. Scopeの対象キーを確認し、Stepの参照と操作対象を設定する。
5. IsEnabledを有効にしてEditorで再生する。

任意のタイミングから起動する案内はTrigger=Manualと任意のTriggerKeyを設定し、画面側で`TutorialManager.Report(TutorialSignal.Manual, "equipment-guide", scope.gameObject)`のように通知する。手動通知でもマスターの開始条件・完了記録・優先順位を適用する。

作成例はExample-HomeMissions、Example-Character、Example-BattlePathの3件。正式内容未指定のためIsEnabled=false。Battle例はStage条件を未設定としており、任意のBattleReadyに対応する設定例。特定Stageだけで再生する場合はCurrentStage条件にStageMasterDataを設定する。

Editorメニュー `The Red Fever/Tutorial/Run Smoke Checks`で独立した一時Sceneとメモリ保存を使った検証を行える。実ユーザーのセーブファイルには書き込まない。

## 8. 残作業

- AngelによるBattleのパス・危険回避・Attack・Skill・Goal説明のマスター作成と有効化。
- Resurgence専用の再生条件、別Tutorial IDと台詞差分の作成。
- Android実機と異なる解像度で手・メッセージ・穴・タッチ入力を確認。
- 未実装の報酬・結末・周回導線に保存処理やready通知を接続。救済条件自体は開示しない。
