# スキル仕様書

- 最終更新: 2026-07-12
- 文書状態: 構想段階
- 位置づけ: 戦闘スキルのデータ責務、効果配列、チャージ、実戦パレット、装備候補スキルとの接続を定義する。戦闘中のパス解決との関係は `docs/specs/戦闘システム仕様書.md` も参照する。

## 1. 基本方針

- スキルは盤面ノードではなく、盤外の Skill パレットから事前選択する。
- 選択中スキルは、そのターン中に通過した `Attack` ノードをスキル行動に変換する。
- スキルデータは `BattleSkillMasterData` で管理する。
- スキル効果は `BattleSkillOperationData` の配列として持つ。
- 1 つのスキルは複数の効果を持てる。
- 効果一覧は初期実装対象だけでなく、将来拡張候補も含めて仕様書に保持する。
- 属性の概念は採用しない。現行実装に残る `BattleSkillMasterData` の属性参照は旧実装として扱い、新仕様では前提にしない。

## 2. スキルマスターデータ

`BattleSkillMasterData` は少なくとも以下を扱う。

- `SkillId`
- `SkillKey`
- `DisplayName`
- `Description`
- `Icon`
- `EffectData`
- `EffectAnimation`
- `RequiredCharge`
- `StartingCharge`
- `TurnChargeGain`
- `AttackChargeGain`

`EffectData` は `BattleSkillOperationData` の配列であり、スキルが実行する効果を上から順に表す。

現行実装には `Attributes` が存在するが、新仕様では使用しない。

## 3. スキル効果データ

`BattleSkillOperationData` は、スキル効果 1 件ぶんを表す。

主な項目は以下とする。

- 効果種別
- 対象タイプ
- 参照パラメータ
- 値種別
- 値
- ダメージ式
- 継続ターン
- 成功率

効果種別は、初期実装対象、近い拡張候補、遠い拡張候補、保留 / アイデアに区分して管理する。

## 4. 効果種別一覧

### 4.1 初期実装対象

| 効果種別 | 概要 |
| --- | --- |
| `Damage` | 敵にダメージを与える |
| `ChargeGain` | 自分またはスキルのチャージを増やす |
| `Heal` | 自分の HP を回復する |
| `GuardGain` | 一時的な Guard または防御値を得る |

初期実装では、まず上記 4 系統を実装対象とする。

### 4.2 近い拡張候補

| 効果種別 | 概要 |
| --- | --- |
| `Buff` | 自分のステータスや `NamedValue` を一時強化する |
| `Debuff` | 敵のステータスや行動性能を一時弱体化する |
| `CooldownOrChargeControl` | スキルチャージの増減、特定スキルの回転補助または阻害を行う |

`Buff` / `Debuff` は、`BattleStatModifiers` 相当の一時補正として扱う。

### 4.3 遠い拡張候補

| 効果種別 | 概要 |
| --- | --- |
| `Status` | 毒、スタン、脆弱などの状態を付与する |
| `BoardManipulation` | 盤面セルの生成、削除、変換を行う |
| `HazardControl` | 危険マスの軽減、消去、移動、弱体化を行う |
| `ExtraAction` | 追加行動、再行動、追加パス入力を行う |

`Status` は、状態の種類、重ねがけ、発火タイミング、UI 表示などの設計が必要なため、近い拡張候補には含めない。

### 4.4 保留 / アイデア

保留 / アイデア枠は、少数の例だけを載せる置き場とする。
増えすぎると仕様の情報量が膨らむため、採用方針が固まったものから該当区分へ移す。

| 効果種別 | 概要 |
| --- | --- |
| `Summon` | 召喚や一時ユニットを扱う |
| `ResourceConvert` | HP をチャージに変換する、チャージを Guard に変換するなどリソースを変換する |
| `RuleOverride` | 1 ターンだけパス接続ルールや危険判定を書き換える |

## 5. 対象タイプ

対象タイプは以下を扱う。

| 対象タイプ | 概要 |
| --- | --- |
| `Self` | 自分 |
| `Enemy` | 敵単体 |
| `AllEnemies` | 敵全体。将来の複数敵用 |
| `None` | 対象なし。特殊効果や盤面効果用 |

味方複数を必要とするゲーム設計にはしないため、`Ally` や `AllAllies` は採用しない。

現行戦闘は 1 対 1 を基本とするが、将来の複数敵に備えて `AllEnemies` は残す。

## 6. 値種別

値種別は以下を扱う。

| 値種別 | 概要 |
| --- | --- |
| `None` | 値なし |
| `FixedValue` | 固定値 |
| `Multiplier` | 参照パラメータに対する倍率 |
| `Percentage` | 割合値 |

`Percentage` は `0.2 = 20%` として扱う。
`20 = 20%` ではない。

## 7. 参照パラメータ

参照パラメータは以下を扱う。

| 参照パラメータ | 概要 |
| --- | --- |
| `None` | 参照なし |
| `Hp` | HP 参照、または HP への効果 |
| `Attack` | 攻撃力参照 |
| `Defense` | 防御、軽減系参照 |
| `Charge` | スキルチャージ参照、またはチャージ増減 |
| `Guard` | Guard 参照、または Guard 増減 |

現行 enum には `Speed` が存在するが、このゲームの戦闘ロジックには合いにくいため削除候補として扱う。

## 8. 複数効果の実行

- 1 つのスキルは複数の効果を持てる。
- 効果は `EffectData` の配列順に上から実行する。
- 各効果は個別に成功 / 失敗を判定できる。
- 途中の効果が失敗しても、原則として後続効果は実行する。
- スキル全体の不発判定は設けない。
- 全効果が失敗しても、スキルチャージは通常どおり消費する。

## 9. 成功率

各効果は `SuccessRate` を持てる。

`SuccessRate` は固定値だけでなく、将来的に以下の条件で補正できるようにする。

- 装備タグ
- 状態
- 盤面結果
- 敵行動
- その他の戦闘中コンテキスト

スキル全体の不発判定は持たないが、全効果に同じ成功率補正をかけることで、実質的にスキル全体が不発したような表現は可能とする。
ただし仕様上はあくまで「全効果が失敗した結果」であり、「スキル全体不発」という別処理は設けない。

## 10. チャージと消費

- `RequiredCharge` は Ready になるために必要なチャージ量である。
- `StartingCharge` は戦闘開始時の初期チャージ量である。
- `TurnChargeGain` はターン経過で加算されるチャージ量である。
- `AttackChargeGain` は Attack 解決時に加算されるチャージ量である。

現行実装では、ターン実行開始時に全スキルへ `TurnChargeGain` が加算される。

`AttackChargeGain` はデータとランタイムメソッドは存在するが、実際に解決された Attack 回数に応じて加算する接続はまだ未実装である。

スキル消費は、戦闘システム側の消費条件に従う。
現行実装では、解決が Goal ノードまで到達し `PathConfirmed` が成立した場合に選択中スキルを消費する。

## 11. Buff / Debuff

`Buff` / `Debuff` は `BattleStatModifiers` 相当の一時補正として扱う。

補正対象は以下を扱う。

- `Parameter`
- `NamedValue`

操作種別は以下を扱う。

- `Set`
- `Add`
- `Multiply`

継続効果は、発動したターンを 0 ターン目として、次ターンから指定ターン数だけ有効とする。

- `durationTurns = 0`: 継続なし
- `durationTurns = 1`: 次の 1 ターンだけ有効
- `durationTurns = 2`: 次の 2 ターン有効

発動した瞬間の同一スキル内ダメージへ乗せる即時補正とは分けて扱う。

## 12. 演出

スキルは `EffectAnimationMasterData` を参照できる。

`EffectAnimationMasterData` は少なくとも以下を持つ。

- `EffectAnimationId`
- `EffectAnimationKey`
- `DisplayName`
- `Description`
- `CharacterAnimationName`
- `VisualEffectKey`
- `SoundEffectKey`
- `WaitSeconds`

現行実装ではデータは存在するが、スキルごとの `EffectAnimationData` を使った実 VFX / SE 再生は未接続である。

## 13. 装備候補スキルとの関係

- 全装備が候補スキルを持てる。
- 1 装備が持てる候補スキルは最大 2 件とする。
- 候補スキルは `BattleSkillMasterData` 参照で持つ。
- 候補スキルは「その装備が提供できるスキル候補」であり、戦闘中に使う実戦用 Skill パレットとは別概念とする。
- 実戦用 Skill パレットは、装備中の各装備が持つ候補スキル群から別途選抜して構成する。

タグはスキルの属性ではなく、装備テーマやビルド傾向を表す。
将来的にタグで `SuccessRate` や `NamedValue` を補正することは許容するが、敵ごとの有利不利表として扱わない。

## 14. 現行実装との差分メモ

現行実装では、以下が新仕様と異なる、または未接続である。

- `BattleSkillMasterData` に属性参照が残っている。
- `BattleDamagePipeline` がスキル攻撃時にスキル属性を参照している。
- `BattleSkillOperationType` は `Damage / Buff / Debuff / Utility` の粗い区分であり、本仕様の効果一覧とはまだ一致していない。
- `BattleSkillTargetType` には `AllEnemies` があるが、現行戦闘は 1 対 1 である。
- `BattleSkillParameterType` に `Speed` が残っている。
- 複数効果を持てるが、現行戦闘解決では主に Damage 効果だけが実処理される。
- `SuccessRate` はデータとして存在するが、戦闘解決にはまだ接続されていない。
- `AttackChargeGain` はデータとして存在するが、実際の Attack 解決数にはまだ接続されていない。
- `EffectAnimationData` は DTO として存在するが、スキル固有の VFX / SE 再生にはまだ接続されていない。
- `SkillSlotRuntime.DescriptionSupplement` は現行実装では空文字固定である。
- `EquipmentMasterData.AssignableSkills` は現行 validation / tooltip 上、最大 3 件想定が残っている。

## 15. 未確定事項

- 正式なスキル名と個別性能
- 各効果の具体的な計算式
- `SuccessRate` 補正のデータ構造
- 同種 `Buff` / `Debuff` の重ねがけ、上書き、延長ルール
- `AllEnemies` を使う複数敵戦闘の詳細
- スキル説明文、成功率、効果一覧を UI でどこまで表示するか
- スキル候補群から実戦用 4 枠を選ぶロードアウト画面と保存形式
