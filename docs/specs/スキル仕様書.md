# スキル仕様書

- 最終更新: 2026-08-16
- 文書状態: 構想段階
- 位置づけ: 戦闘スキルのデータ責務、効果配列、チャージ、実戦パレット、装備候補スキルとの接続を定義する。戦闘中のパス解決との関係は `docs/specs/戦闘システム仕様書.md` も参照する。

## 1. 基本方針

- スキルは盤面ノードではなく、盤外の Skill パレットから事前選択する。
- 選択中スキルは、そのターン中に通過した `Attack` ノードをスキル行動に変換する。
- スキルデータは `BattleSkillMasterData` で管理する。
- スキル効果は `BattleSkillOperationData` の配列として持つ。
- 1 つのスキルは複数の効果を持てる。
- 効果一覧は初期実装対象だけでなく、将来拡張候補も含めて仕様書に保持する。
- 属性の概念は採用しない。現行実装に残る `BattleSkillMasterData` の属性参照は旧実装として扱い、新仕様では前提にしない。

## 2. スキルマスターデータ

`BattleSkillMasterData` は少なくとも以下を扱う。

- `SkillId`
- `SkillKey`
- `DisplayName`
- `Description`
- `Icon`
- `EffectData`
- `EffectAnimation`
- `RequiredCharge`
- `StartingCharge`
- `TurnChargeGain`
- `AttackChargeGain`

`EffectData` は `BattleSkillOperationData` の配列であり、スキルが実行する効果を上から順に表す。

旧属性実装の互換 field は残っているが、新仕様では使用しない。
runtime DTO と `SkillSlotRuntime` には属性情報を流さない。

## 3. スキル効果データ

`BattleSkillOperationData` は、スキル効果 1 件ぶんを表す。

主な項目は以下とする。

- 効果種別
- 対象タイプ
- 参照パラメータ
- 値種別
- 値
- ダメージ式
- 継続ターン
- 成功率

効果種別は、初期実装対象、近い拡張候補、遠い拡張候補、保留 / アイデアに区分して管理する。

## 4. 効果種別一覧

### 4.1 初期実装対象

| 効果種別 | 概要 |
| --- | --- |
| `Damage` | 敵にダメージを与える |
| `ChargeGain` | 自分またはスキルのチャージを増やす |
| `Heal` | 自分の HP を回復する |
| `GuardGain` | 一時的な Guard または防御値を得る |

初期実装では、まず上記 4 系統を実装対象とする。

### 4.2 近い拡張候補

| 効果種別 | 概要 |
| --- | --- |
| `Buff` | 自分のステータスや `NamedValue` を一時強化する |
| `Debuff` | 敵のステータスや行動性能を一時弱体化する |
| `CooldownOrChargeControl` | スキルチャージの増減、特定スキルの回転補助または阻害を行う |

`Buff` / `Debuff` は、`BattleStatModifiers` 相当の一時補正として扱う。

### 4.3 遠い拡張候補

| 効果種別 | 概要 |
| --- | --- |
| `Status` | 毒、スタン、脆弱などの状態を付与する |
| `BoardManipulation` | 盤面セルの生成、削除、変換を行う |
| `HazardControl` | 危険マスの軽減、消去、移動、弱体化を行う |
| `ExtraAction` | 追加行動、再行動、追加パス入力を行う |

`Status` は、状態の種類、重ねがけ、発火タイミング、UI 表示などの設計が必要なため、近い拡張候補には含めない。

### 4.4 保留 / アイデア

保留 / アイデア枠は、少数の例だけを載せる置き場とする。
増えすぎると仕様の情報量が膨らむため、採用方針が固まったものから該当区分へ移す。

| 効果種別 | 概要 |
| --- | --- |
| `Summon` | 召喚や一時ユニットを扱う |
| `ResourceConvert` | HP をチャージに変換する、チャージを Guard に変換するなどリソースを変換する |
| `RuleOverride` | 1 ターンだけパス接続ルールや危険判定を書き換える |

## 5. 対象タイプ

対象タイプは以下を扱う。

| 対象タイプ | 概要 |
| --- | --- |
| `Self` | 自分 |
| `Enemy` | 敵単体 |
| `AllEnemies` | 敵全体。将来の複数敵用 |
| `None` | 対象なし。特殊効果や盤面効果用 |

味方複数を必要とするゲーム設計にはしないため、`Ally` や `AllAllies` は採用しない。

現行戦闘は 1 対 1 を基本とするが、将来の複数敵に備えて `AllEnemies` は残す。

現行実装では、初期実装済みの効果種別は対象が固定される。
`Damage` / `Debuff` は `Enemy` または将来用の `AllEnemies`、`ChargeGain` / `Heal` / `GuardGain` / `Buff` は `Self` として扱う。
`BattleSkillOperationData.OnValidate` は、この範囲の矛盾した `TargetType` を現行ルールへ正規化する。

## 6. 値種別

値種別は以下を扱う。

| 値種別 | 概要 |
| --- | --- |
| `None` | 値なし |
| `FixedValue` | 固定値 |
| `Multiplier` | 参照パラメータに対する倍率 |
| `Percentage` | 割合値 |

`Percentage` は `0.2 = 20%` として扱う。
`20 = 20%` ではない。

## 7. 参照パラメータ

参照パラメータは以下を扱う。

| 参照パラメータ | 概要 |
| --- | --- |
| `None` | 参照なし |
| `Hp` | HP 参照、または HP への効果 |
| `Attack` | 攻撃力参照 |
| `Defense` | 防御、軽減系参照 |
| `Charge` | スキルチャージ参照、またはチャージ増減 |
| `Guard` | Guard 参照、または Guard 増減 |

旧 `Speed` は `BattleSkillParameterType.LegacySpeed = 4` として互換用に残す。
新仕様の戦闘計算では使用せず、スキル効果や補正で指定されても無視する。

## 8. 複数効果の実行

- 1 つのスキルは複数の効果を持てる。
- 効果は `EffectData` の配列順に上から実行する。
- 各効果は個別に成功 / 失敗を判定できる。
- 途中の効果が失敗しても、原則として後続効果は実行する。
- スキル全体の不発判定は設けない。
- 全効果が失敗しても、スキルチャージは通常どおり消費する。

現行実装では、選択中 Skill が Attack ノードで解決されたとき、`EffectData` を配列順に action 化する。
`Damage` 効果はダメージ計算へ接続済みである。
`ChargeGain`、`Heal`、`GuardGain` は初期効果として戦闘解決へ接続済みである。
`SuccessRate` は効果ごとに判定し、失敗した効果は no-op action として記録したうえで後続効果を止めない。
各効果 action は `SkillEffectIndex` と `EffectAnimationData` を持ち、表示層では Skill 開始 beat の後に効果ごとの beat として配列順に展開される。

## 9. 成功率

各効果は `SuccessRate` を持てる。

`SuccessRate` は固定値だけでなく、将来的に以下の条件で補正できるようにする。

- 装備タグ
- 状態
- 盤面結果
- 敵行動
- その他の戦闘中コンテキスト

スキル全体の不発判定は持たないが、全効果に同じ成功率補正をかけることで、実質的にスキル全体が不発したような表現は可能とする。
ただし仕様上はあくまで「全効果が失敗した結果」であり、「スキル全体不発」という別処理は設けない。

現行実装では `BattleSkillEffectSuccessResolver` が `SuccessRate` を解決する。

- preview では乱数を振らず、成功率が 0 より大きい効果を成功扱いにして安定表示する。
- 実行時は `UnityEngine.Random.value` による 0.0 以上 1.0 以下の乱数で効果ごとに成否判定する。
- `BattleSkillEffectSuccessRateModifier` を追加することで、タグ、状態、盤面結果、敵行動などによる成功率補正を後から差し込める。
- action / summary には効果の成功 / 失敗数を残すが、初期 UI では詳細な失敗ログを常設表示しない。

## 10. チャージと消費

- `RequiredCharge` は Ready になるために必要なチャージ量である。
- `StartingCharge` は戦闘開始時の初期チャージ量である。
- `TurnChargeGain` はターン経過で加算されるチャージ量である。
- `AttackChargeGain` は Attack 解決時に加算されるチャージ量である。

現行実装では、ターン実行開始時に全スキルへ `TurnChargeGain` が加算される。
プレビュー計算では、実データを変更せず、選択中 Skill のクローンへ `TurnChargeGain` を反映した状態で効果量を評価する。

`AttackChargeGain` はデータとランタイムメソッドは存在するが、実際に解決された Attack 回数に応じて加算する接続はまだ未実装である。

`ChargeGain` 効果は、初期実装では選択中 Skill 自身のチャージを増やす。
消費条件を満たしたターンでは、スキル消費後に `ChargeGain` を反映する。
そのため、`RequiredCharge` 3 の Skill が `ChargeGain = 1` を持つ場合、使用後のチャージは 0 ではなく 1 になる。

`Heal` 効果はプレイヤー HP を回復する。
回復量は現在 HP と最大 HP から実回復量へ丸め、最大 HP を超えない。

`GuardGain` 効果は同一ターン内の一時 Guard として扱う。
得た Guard は後続のプレイヤー被ダメージを吸収し、そのターンの解決内で消費される。
現時点ではターンをまたいで保持する Guard リソースや専用 UI には接続しない。

スキル消費は、戦闘システム側の消費条件に従う。
現行実装では、解決が Goal ノードまで到達し `PathConfirmed` が成立した場合に選択中スキルを消費する。

## 11. Buff / Debuff

`Buff` / `Debuff` は `BattleStatModifiers` 相当の一時補正として扱う。

補正対象は以下を扱う。

- `Parameter`
- `NamedValue`

操作種別は以下を扱う。

- `Set`
- `Add`
- `Multiply`

継続効果は、発動したターンを 0 ターン目として、次ターンから指定ターン数だけ有効とする。

- `durationTurns = 0`: 継続なし
- `durationTurns = 1`: 次の 1 ターンだけ有効
- `durationTurns = 2`: 次の 2 ターン有効

発動した瞬間の同一スキル内ダメージへ乗せる即時補正とは分けて扱う。

現行実装では、`Buff` / `Debuff` はターン終了時に一時補正として session へ予約し、次ターン以降の `BattleTurnContext` 生成時に stats へ反映する。

- `DurationTurns <= 0` の効果は、成功しても継続補正を作らない。
- `DurationTurns = 1` は次の 1 ターンだけ有効で、そのターンの解決後に消える。
- 現行 `BattleSkillOperationData` には `NamedValueKey` や明示的な `Set / Add / Multiply` がないため、初期実装では `ParameterType` を対象にする。
- `FixedValue` は加算補正として扱う。`Buff` は `+Value`、`Debuff` は `-Value` に変換する。
- `Multiplier` は指定倍率をそのまま `Multiply` として扱う。
- `Percentage` は `Buff` では `1 + Value`、`Debuff` では `1 - Value` の `Multiply` として扱う。
- `ParameterType.None` と旧 `LegacySpeed` は補正対象なしとして扱う。
- `NamedValue` 補正は、スキル効果データ側に key / operation を持たせるまで未接続とする。

## 12. 演出

スキルは `EffectAnimationMasterData` を参照できる。

`EffectAnimationMasterData` は少なくとも以下を持つ。

- `EffectAnimationId`
- `EffectAnimationKey`
- `DisplayName`
- `Description`
- `CharacterAnimationName`
- `VisualEffectKey`
- `SoundEffectKey`
- `WaitSeconds`

現行実装では、`EffectAnimationData.CharacterAnimationName` が既存 `BattlePlayerAnimationCue` に対応する場合、Skill 効果 beat でそのキャラクター animation を再生する。
対応 animation が無い場合は `WaitSeconds` の待機だけで効果成立タイミングを作る。
`VisualEffectKey` と `SoundEffectKey` は Timeline 上で参照され、Debug.Log で確認できる。
実際の VFX / SE オブジェクト生成や Audio 再生は未接続である。

## 13. 装備候補スキルとの関係

- 全装備が候補スキルを持てる。
- 1 装備が持てる候補スキルは最大 2 件とする。
- 候補スキルは `BattleSkillMasterData` 参照で持つ。
- 候補スキルは「その装備が提供できるスキル候補」であり、戦闘中に使う実戦用 Skill パレットとは別概念とする。
- 実戦用 Skill パレットは、装備中の各装備が持つ候補スキル群から別途選抜して構成する。
- 実戦用 Skill パレットは `UserProfileData.SkillLoadout.SkillIds` に 4 枠固定で保存する。
- 既存の `SkillSlotSkillIds` は互換フィールドとして残し、保存正規化時に `SkillLoadout.SkillIds` と同期する。
- 初期仕様では、武器ごとの固定 Skill パレットマスターは持たず、保存済みロードアウトだけを正とする。
- ロードアウト選択画面は、現在装備中の `AssignableSkills` を候補として表示し、候補外 SkillId は保存時に 0 へ落とす。

現行デモデータでは、装備種類ごとに 2 件ずつ Demo Skill を用意し、各装備の `AssignableSkills` に割り当てている。
Demo Skill は `SkillId` 2101 から 2130 を使い、`Damage`, `Heal`, `GuardGain`, `ChargeGain` の初期実装済み効果だけで構成する。
正式なスキル名、個別性能、装備ごとの固有割り当てが決まるまでの一時データとして扱う。

タグはスキルの属性ではなく、装備テーマやビルド傾向を表す。
将来的にタグで `SuccessRate` や `NamedValue` を補正することは許容するが、敵ごとの有利不利表として扱わない。

## 14. 現行実装との差分メモ

現行実装では、以下が新仕様と異なる、または未接続である。

- `BattleSkillMasterData` には既存 asset 保護用の旧属性 field が残っている。
- `BattleDamagePipeline` はスキル攻撃時に属性を参照しない。
- `BattleSkillOperationType` は `Damage / ChargeGain / Heal / GuardGain` と、近い拡張候補・遠い拡張候補・保留候補を持つ enum へ整理済みである。
- 既存 asset 互換のため、旧 `Utility = 3` は `ChargeGain = 3` として読み替える。
- 旧 `Buff = 1` / `Debuff = 2` は互換用の `LegacyBuff` / `LegacyDebuff` として残し、新規データでは `Buff = 20` / `Debuff = 21` を使う。
- `BattleSkillTargetType` には `AllEnemies` があるが、現行戦闘は 1 対 1 である。
- `BattleSkillOperationData.OnValidate` は、現行実装済み効果の `TargetType` を効果種別に合う値へ正規化する。
- `BattleSkillParameterType.Speed` は active parameter から外し、既存 serialized data 保護用の `LegacySpeed = 4` として残している。
- スキル効果は `EffectData` の配列順に action 化される。
- `Damage`、`ChargeGain`、`Heal`、`GuardGain` は初期効果として戦闘解決へ接続済みである。
- `Buff` / `Debuff` は Parameter 対象の一時補正として戦闘解決へ接続済みである。
- Damage 効果が存在しないスキルは、Damage 計算では 0 ダメージとして扱う。
- `SuccessRate` は戦闘解決へ接続済みで、preview は安定表示、実行時は効果ごとに乱数判定する。
- `AttackChargeGain` はデータとして存在するが、実際の Attack 解決数にはまだ接続されていない。
- `EffectAnimationData.CharacterAnimationName` と `WaitSeconds` は Skill 効果 Timeline へ接続済みである。
- `EffectAnimationData.VisualEffectKey` / `SoundEffectKey` は Timeline へ載るが、スキル固有の VFX / SE 実再生にはまだ接続されていない。
- `SkillSlotRuntime.DescriptionSupplement` は `RequiredCharge`、開始チャージ、ターンチャージ、Attack チャージを自動補足する。
- `EquipmentMasterData.AssignableSkills` は validation / tooltip / DTO 変換上、最大 2 件へ反映済みである。
- `EquipmentMasterData.DanceSkill` はアイテム相当の装備が提供する Dance 効果の受け口として DTO へ変換される。

## 15. 未確定事項

- 正式なスキル名と個別性能
- 各効果の具体的な計算式
- `SuccessRate` 補正に使うタグ、状態、盤面結果、敵行動などの具体値とデータ入力元
- 同種 `Buff` / `Debuff` の重ねがけ、上書き、延長ルール
- Skill 効果で `NamedValue` 補正を指定するための key / operation データ構造
- `AllEnemies` を使う複数敵戦闘の詳細
- スキル説明文、成功率、効果一覧を UI でどこまで表示するか
- 独立アイテム枠と `DanceSkill` の正式な装備枠対応
