# 戦闘画面仕様書

- 最終更新: 2026-08-26
- 文書状態: 初稿
- 位置づけ: 本書は `BattleScene` の画面構成、UI パーツ、表示責務を定義する。戦闘ルールそのものは `docs/specs/戦闘システム仕様書.md` を正とする。

## 1. 基本方針

戦闘画面は縦長画面を前提に設計する。
初期想定は 9:16 の縦長であり、横長画面への最適化は本書の初期スコープ外とする。

画面設計では、盤面操作を最優先する。
プレイヤーが毎ターン行う主操作は盤面グリッドへのパス入力であるため、盤面の視認性、タッチしやすさ、パスの分かりやすさを他の演出や情報表示より優先する。

UI 情報は、できるだけその情報の持ち主の近くに置く。

- 敵名、敵 HP、敵Skill由来の状態・ゲージは `EnemyUnitView` に置く
- プレイヤー HP とプレイヤー状態は `PlayerAreaView` に置く
- Skill の準備状態、選択状態、消費予定は `SkillPaletteView` に置く
- ダメージ量は対象付近の `DamageFeedbackView` で伝える
- 短命な技名、状態変化、回避、被弾、Goal 到達などは `BattleEventNoticeView` で通知する

最上部 HUD は、戦闘全体に 1 つだけ存在する固定情報に限定する。
敵に紐づく情報を最上部 HUD に固定しない。

## 2. 画面領域

縦長戦闘画面は、上から順に以下の領域で構成する。

```text
[ 最上部HUD ]
Turn / Wave / メニュー / 一時停止など

[ 上部バトル演出領域 ]
EnemyArea / PlayerArea / DamageFeedback / セリフ / 戦闘イベント通知

[ 中央〜下部 情報・コマンド領域 ]
Skill パレット / 選択中 Skill / 必要な一時詳細

[ 最下部 メイン操作領域 ]
盤面グリッド / ノード / パス線 / 入力フィードバック

[ Overlay ]
勝利 / 敗北 / リトライ / 次ステージ / メニュー
```

### 2.1 最上部 HUD

最上部 HUD は、戦闘全体の固定情報だけを扱う。

初期候補:

- Turn
- Wave
- メニュー
- 一時停止

ここには置かないもの:

- 敵名
- 敵 HP
- 敵Skill由来の状態・ゲージ
- 敵ごとの状態
- プレイヤー HP
- Skill 状態
- 行動ログ
- 常設の確認文言

敵やプレイヤーに紐づく情報は、それぞれ `EnemyUnitView`、`PlayerAreaView`、`SkillPaletteView` へ置く。

### 2.2 上部バトル演出領域

上部バトル演出領域は、戦闘の見た目と対象に紐づく情報を扱う。

含める UI:

- `EnemyAreaView`
- `EnemyUnitView`
- `PlayerAreaView`
- `DamageFeedbackView`
- `BattleEventNoticeView`
- セリフ、フレーバー、演出用短文
- キャラクターアニメーション、VFX、SE の起点

初期実装では、プレイヤーと敵の `AppearanceController` をそれぞれ保持し、ターン解決で生成された `ResolvedActions` から演出 beat を作ってキャラクターアニメーションを再生する。
単独 action は解決列の順に再生し、敵の `NormalAttack` / `Skill` / `Dance` も敵側アニメーションとして扱う。

危険マス接触時は、敵の攻撃演出を `EnemyIntent` として解決列に載せる。
`JumpPrepared` / `RollPrepared` の直後に `EnemyIntent` と `HazardEvaded` が続く場合は、プレイヤーの回避アニメーションと敵の攻撃アニメーションを同じ beat で扱い、敵側 `AttackStart` イベントを受けて回避アニメーションを開始する。
同じ beat 内でも各キャラクターの再生終了と Idle 復帰は独立して扱うため、短い回避アニメーションが敵攻撃の終了まで繰り返されないようにする。
被弾時は `EnemyIntent` と `HazardHit` を同じ beat で扱うが、プレイヤーの `Stun` は敵側 `Hit` イベントを受けて開始する。
各アニメーションは `RecoverEnd` イベントを受けて終了扱いにし、イベントが無い場合だけクリップ長またはフォールバック秒数で進行する。
HP、回復、ダメージ表示、短命通知は、ターン終了後の一括反映ではなく、演出 event に紐づく action 成立タイミングで更新する。
通常攻撃や Skill は自身の `Hit` event、被弾は敵側 `Hit` を受けた `Stun` 開始時を基準にする。
Skill の複数効果は、Skill 開始演出の後に効果ごとの beat として配列順に展開する。
各効果は `EffectAnimationData.CharacterAnimationName` が既存 animation に対応する場合はその animation を再生し、対応しない場合は `WaitSeconds` の待機だけで成立タイミングを作る。
VFX / SE は現時点ではキーを Timeline に載せて Debug.Log に出す段階であり、実再生は今後の接続対象とする。

初期実装では敵 1 体を主対象にする。
ただし、敵情報は `EnemyUnitView` に閉じ込め、将来複数敵になった場合は `EnemyAreaView` が複数の `EnemyUnitView` を管理できるようにする。

複数敵時の詳細なレイアウト、情報密度、選択中敵の強調表示は、複数敵実装時に改めて設計する。
現時点では、複数敵のために単体敵画面の見やすさを犠牲にしない。

### 2.3 中央〜下部 情報・コマンド領域

情報・コマンド領域は、プレイヤーがパス入力前に選ぶものを扱う。

含める UI:

- `SkillPaletteView`
- `SkillSlotView`
- 選択中 Skill のハイライト
- Ready / Charging / Locked / Empty の見分け
- 必要な場合のみ Skill 詳細の一時表示

常設の確認・プレビュー文言は置かない。
Skill 消費予定は、テキストではなく Skill パレット側の見た目で伝える。

### 2.4 最下部 メイン操作領域

メイン操作領域は盤面グリッドを扱う。
盤面は最下部に置き、親指でなぞりやすい位置にする。
ただし、OS のホームバーや端末の安全領域に触れすぎないように下余白を持たせる。

含める UI:

- `BattleBoardView`
- `BattleCellView`
- `BattleTraceLineView`
- ノード表示
- 危険表示
- Start / Goal 表示
- パス入力
- 不正入力時の視覚フィードバック

盤面セルは正方形を基本とする。
盤面全体の表示サイズは、列数、行数、画面幅から計算して調整する。

9:16 縦長で、盤面幅を画面幅いっぱいにした場合の画面高さ占有率は以下で求める。

```text
盤面高さ比率 = 行数 / 列数 x 9 / 16
```

現行想定の 5 列 x 6 行では、画面幅いっぱいにすると画面高の 67.5% を占める。
幅を絞る場合の目安は以下。

| 盤面幅 | 5x6 盤面の高さ |
| --- | --- |
| 100% | 67.5% |
| 90% | 60.8% |
| 80% | 54.0% |
| 75% | 50.6% |
| 70% | 47.3% |
| 67% | 45.2% |

初期目安としては、5x6 盤面を画面幅 75〜80% 程度に収め、盤面高さを画面高の 50〜54% 程度にする。
ただし、実機でタッチしづらい場合は盤面サイズを優先して調整する。

### 2.5 Overlay

Overlay は、戦闘進行を一時停止または終了させる画面全体表示に使う。

含める UI:

- 勝利
- 敗北
- リトライ
- 次ステージ
- ステージ選択へ戻る
- メニュー
- 一時停止

Overlay は盤面操作や Skill 操作より優先して表示し、背面の入力を受け付けない。

## 3. 戦闘イベント通知

戦闘イベント通知は `BattleEventNoticeView` として扱う。
これは履歴ログではなく、戦闘中に発生した短命な出来事を一時的に表示してすぐ消す UI である。

主な表示例:

- Skill 名
- Attack / Jump / Roll / Dance などの発生
- 回避
- 被弾
- Goal 到達
- 危険が増した
- 敵が体勢を変えた
- 次の盤面が乱れる

表示位置は上部バトル演出領域の上寄りを基本とする。
対象に強く紐づく通知は、演出上 PlayerArea または EnemyArea 側へ寄せてもよい。

戦闘イベント通知は、重要情報を永続的に保持しない。
発生を知らせた後、継続中の状態は以下のように各 UI の見た目へ残す。

- 危険強化中: 盤面の危険マスの色、エフェクト、敵側の状態表示
- Skill 選択中: `SkillPaletteView` のハイライト
- 被弾結果: ダメージ表示、HP 表示、キャラクター演出
- Goal 到達: Goal 演出、解決演出

## 4. 入力フィードバック

常設の確認・プレビュー文言は作らない。
入力状態や結果予測は、それぞれの UI 表現へ分担する。

### 4.1 正常入力

正常入力中は、以下で伝える。

- 通過済みセルのハイライト
- 現在セルのハイライト
- 確定可能状態の Goal / パス線の色変化
- Goal 到達時の短い戦闘イベント通知

通常プレイ中のターン実行は、実際に引いたパスを Goal 到達後に指を離して確定したときだけ開始する。
未確定パスで実行要求が来た場合は、常設確認文言ではなく `BattleEventNoticeView` の短命通知で引き直しを促す。

### 4.2 不正入力

不正入力は、テキストの常設表示ではなく、盤面付近の演出で伝える。

候補:

- 該当セルまたはパス線を赤く光らせる
- パス線を短く揺らす
- 端末のバイブレーションを使う
- 短いトーストを出す

不正入力の例:

- 隣接していない
- 同じマスを再訪した
- 線が交差した
- Goal 到達前に指を離した
- Goal 到達後に延長しようとした

トーストを使う場合も、メイン画面に履歴として残さない。

### 4.3 結果予測

初期仕様では、`敵 -120 / 自分 -30 / Goal 到達` のような常設の一行結果予測は置かない。

結果は以下で伝える。

- HP の減少
- ダメージ表示
- Skill スロットの消費/チャージ変化
- 盤面演出
- 戦闘イベント通知

将来、判断が難しいと感じた場合は、文字ではなく HP バーの予測減少、危険マスの強調、Skill スロットの消費予定演出などで補う。

## 5. 行動ログ

初期画面には、行動ログの履歴表示を置かない。

理由:

- 縦長画面では盤面と Skill パレットの面積を優先したい
- 履歴ログがあると画面情報量が増え、読ませるゲームに寄りやすい
- 技名、回避、被弾、Goal 到達などは戦闘イベント通知と演出で十分に伝えられる

ただし、Debug.Log や開発用ログは残してよい。
将来必要になった場合は、リザルト詳細や戦闘履歴画面として別導線で扱う。

## 6. UI パーツ責務

| パーツ | 役割 | 初期方針 |
| --- | --- | --- |
| `BattleScreenRoot` | 戦闘画面全体の領域管理 | 縦長 9:16 前提の親レイアウトを持つ |
| `BattleTopHudView` | 戦闘全体の固定情報 | Turn / Wave / メニュー程度に絞る |
| `BattlePresentationView` | 上部バトル演出領域の親 | 敵、プレイヤー、通知、ダメージの配置を管理する |
| `EnemyAreaView` | 敵表示領域 | 初期は 1 体、将来複数 `EnemyUnitView` を管理する |
| `EnemyUnitView` | 1 体ぶんの敵表示 | 敵名、敵 HP、敵Skill由来の状態・ゲージを持つ |
| `PlayerAreaView` | プレイヤー表示 | プレイヤー HP、プレイヤー状態、キャラ演出を持つ |
| `DamageFeedbackView` | ダメージ表示 | 対象付近にダメージ値を表示する |
| `BattleEventNoticeView` | 戦闘イベント通知 | 短命な技名、状態変化、Goal、回避、被弾を出して消す |
| `SkillPaletteView` | Skill パレット | 4 スロットと選択状態を管理する |
| `BattleSkillSlotView` | 1 スロットぶんの Skill 表示 | `PartsSkillItem` を使って Ready / Charging / Locked / Empty、アイコン、チャージ、選択状態を表示する。現時点では Script 作成済みで、BattleScene の配線は未実施。 |
| `BattleBoardView` | 盤面領域全体 | セル生成/更新、盤面サイズ調整、入力可能領域を管理する |
| `BattleCellView` | 1 マスぶんの表示 | ノード、危険、通過状態、現在位置、確定可能状態を表示する |
| `BattleTraceLineView` | パス線表示 | 入力中の線、確定可能状態、不正入力演出を表示する |
| `BattleResultOverlayView` | 戦闘結果表示 | 勝利、敗北、リトライ、次ステージを表示する |

## 7. 現行実装との差分

現行実装では、`BattleSceneController` が scene 上の `HudPanel`、`BoardPanel`、`SkillSlotArea`、`ActionLogPanel`、`DamageFeedbackPanel`、`EnemyBattleTypePanel`、`NarrativePanel`、`ResultPanel` などを参照している。

現行の特徴:

- `BattleBoardController` は `Panels` を生成先 root として使う
- 既存 child を無効化し、`BattleCellView` prefab を runtime 生成する
- `BattleHudController` が turn、wave、敵名、HP、confirmText などをまとめて扱う
- `ActionLogView` と `NarrativeView` は履歴ログやセリフを表示できる
- 旧属性相性のプレビュー文言やログ表示が残っている

新方針との差分:

- 盤面は `BattleBoardView` が領域全体を所有する
- セルを runtime 生成してもよいが、生成責務は `BattleBoardView` 内に閉じる
- 汎用 `Panels` に盤面セルだけを流し込む構造は本仕様の最終形ではない
- `BattleHudController` は最上部 HUD、敵、プレイヤー、Skill、盤面に責務分割する
- `confirmText` の常設枠は廃止する
- 行動ログの履歴表示は初期画面から外す
- 短命な表示は `BattleEventNoticeView` に寄せる
- 敵名、敵 HP、敵Skill由来の状態・ゲージは `EnemyUnitView` に寄せる
- プレイヤー HP は `PlayerAreaView` に寄せる
